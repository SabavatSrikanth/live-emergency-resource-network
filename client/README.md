# Live Emergency Resource Network (LERN) - Frontend

This is the frontend client for the **Live Emergency Resource Network (LERN)**, a real-time crisis management and resource allocation platform built with React and Vite.

## 🚀 Live Demo
You can test the deployed application here: **[LERN Live Demo](https://live-emergency-resource-network-cli.vercel.app/)**

LERN empowers Citizens to report emergencies, Volunteers to react and manage on-the-ground situations, and Administrators (like Dispatchers and Government Admins) to coordinate responses and deploy AI-driven Triage Plans.

## Features

- **Role-Based Dashboards:** Unique interfaces and permissions for Citizens, Volunteers, and Admins.
- **Real-Time Incident Tracking:** Powered by Socket.io, users can see emergencies pop up and change status in real-time without refreshing the page.
- **AI Triage Integration:** Admins can view and deploy automated emergency response plans generated by an AI assistant based on incident severity and category.
- **Resource Management:** Track live availability of Hospital Beds, Ambulances, Rescue Squads, and Fire Tenders.

## Tech Stack

- **Framework:** React + Vite
- **Styling:** Tailwind CSS / Vanilla CSS + Framer Motion for animations
- **State Management:** Zustand (for Auth and Incident state)
- **Networking:** Axios (HTTP) + Socket.io-client (WebSockets)
- **Icons:** Lucide React

## Getting Started Locally

### Prerequisites
Make sure you have Node.js installed. You will also need the backend server running locally (or pointing to the production backend).

### 1. Install Dependencies
```bash
npm install
```

### 2. Environment Variables
Create a `.env` file in the root of the `client` directory (you can copy `.env.example` if it exists).

```env
# URL to the backend API. 
# For local development: http://localhost:5000
# For production: Your deployed backend URL
VITE_API_URL=http://localhost:5000
```

### 3. Run the Development Server
```bash
npm run dev
```
The application will start at `http://localhost:5173`.

## How Authentication Works

The application uses **JWT (JSON Web Tokens)**. 
- When you register or log in, the backend sends back an `accessToken`.
- This token is saved in your browser's `localStorage`.
- Our Axios interceptor (in `src/services/api.js`) automatically attaches this token as a `Bearer` header to every API request you make.
- If the token expires or is invalid, you will be redirected to the login page.

## Real-Time Updates (Socket.io)

We use WebSockets to ensure that when an emergency happens, everyone knows immediately.
- The connection is established in `src/services/socket.js`. It defaults to your `VITE_API_URL`.
- When an incident is created or updated by anyone (e.g., an Admin deploys an AI plan), the backend emits a socket event.
- Zustand (`useIncidentStore.js`) listens for these events and instantly updates the UI for all connected users.
